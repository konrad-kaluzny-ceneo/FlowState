## Research findings (2026-07-30)

The blocking question was "data model for weekly aggregation." Resolution: **no new persisted table is needed** — the gap is in the query layer, plus one real product decision.

**Reusable today:**
- `Cycle` rows (`startedAt`/`endedAt`/`kind`/`state`/`taskId`) are retained indefinitely, no pruning server- or guest-side — a month of history is small and cheap to scan for a single user.
- `aggregateDayStats` (`src/lib/recap/aggregate-day-stats.ts`) is a pure function over `CycleRow[]` + `activeCount` — reusable per day-bucket without modification.
- `DayPlan` (`prisma/schema.prisma`, keyed `userId`+`localDateKey`) already persists **planned** `focusBudgetMinutes` per day — most of the "planned" side of plan-vs-execution already exists.
- Context-switch frequency needs no schema change: order a day's WORK cycles by `startedAt` and count `taskId` changes between consecutive cycles.

**The actual gap — query layer:**
- `recap.getDayStats` (`src/server/api/routers/recap.ts`) and guest's `buildGuestDayStats` (`src/lib/guest/day-stats.ts`) both **ignore their `localDateKey` input** and hardcode a rolling-24h-from-`now` window. Neither can currently query an arbitrary past day, let alone a week/month range. This must be generalized to accept a real date range with local-day bucketing (client supplies local-midnight boundaries, same pattern as elsewhere in the codebase).
- `DayPlan.usedFocusMinutes` is **deliberately capped at `focusBudgetMinutes`** (`src/lib/day-plan/increment-used-focus-minutes.ts`) — a no-op once a user's actual focus exceeds their plan. It cannot serve as "actual" for trend charts. **Actual** must be recomputed from raw `Cycle` rows via the same honest-totals path (`computeCycleFocusedMinutes`) Podsumowanie already uses; `DayPlan` should only supply the **planned** side of the comparison.
- No rollup/snapshot table appears necessary for MVP given low per-user cycle volume; on-the-fly range aggregation should perform fine. A rollup table is a viable future optimization, not a prerequisite.
- Charts today are hand-rolled inline SVG (no charting library) — extending to weekly/monthly trend charts can follow the same convention, or introduce a lightweight lib; a plan-time decision, not a research blocker.
